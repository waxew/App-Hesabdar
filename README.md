# حسابدار (App-Hesabdar)

نرم‌افزار حسابداری فارسی اندروید با رویکرد Offline-First و دیتابیس کاملاً محلی. هدف پروژه ساخت یک هسته حسابداری مستقل و قابل‌گسترش در کلاس نرم‌افزارهای حسابداری عمومی است؛ طراحی، کد و رابط کاربری این پروژه مستقل هستند.

## وضعیت فعلی

- نسخه: `0.11.0 Beta`
- `versionCode = 6`
- `applicationId = com.waxew.hesabdar`
- Room Schema: `5`
- Kotlin + Jetpack Compose + Material 3
- Room + SQLite
- `minSdk = 24`
- `targetSdk = 35`
- رابط فارسی و RTL
- تاریخ شمسی داخلی
- بدون وابستگی اجباری به اینترنت یا سرور

## ساختار دیتابیس

Room Schema فعلی نسخه `5` است. جداول اصلی:

- `persons`
- `products`
- `invoices`
- `invoice_items`
- `payments`
- `inventory_movements`
- `treasury_accounts`
- `ledger_accounts`
- `journal_documents`
- `journal_lines`
- `checks`
- `installments`
- `cash_entries`
- `audit_logs`
- `document_sequences`

Migrationهای `1 -> 2`، `2 -> 3`، `3 -> 4` و `4 -> 5` صریح هستند و داده‌های نسخه‌های قبلی را حذف نمی‌کنند.

## اصول توسعه غیرقابل‌تغییر

1. اطلاعات اصلی کاربر داخل گوشی ذخیره می‌شود.
2. برای مبالغ مالی از `Long` استفاده می‌شود، نه `Float` و `Double`.
3. هر تغییر Room Schema باید Migration صریح داشته باشد.
4. در Production از `fallbackToDestructiveMigration` استفاده نمی‌شود.
5. `applicationId` ثابت می‌ماند تا نسخه‌های جدید روی نسخه قبلی نصب شوند.
6. عملیات چندجدولی مالی Atomic و Transactional هستند.
7. فاکتور و عملیات مالی از Repository/Engine مرکزی عبور می‌کنند.
8. سند نهایی حذف مستقیم نمی‌شود؛ اصلاحات مهم با Audit/Reversal انجام می‌شوند.
9. تاریخچه مالی با Audit Trail قابل ردیابی نگه داشته می‌شود.
10. Keystore خصوصی Release داخل Repository عمومی Commit نمی‌شود.

## Build و تست

GitHub Actions برای هر Push روی `main` و `develop-v1` ابتدا Unit Test و سپس Build را اجرا می‌کند:

```bash
gradle :app:testDebugUnitTest --stacktrace
gradle :app:assembleDebug --stacktrace
```

Artifact Beta:

```text
App-Hesabdar-v0.11.0-beta-debug
```

Unit Testهای فعلی علاوه بر تاریخ شمسی، محاسبات تخفیف/مالیات/حمل و فرمت شماره اسناد را کنترل می‌کنند.

## مسیر ادامه توسعه

- Draft واقعی فاکتور و تبدیل Draft به Posted
- اصلاح سند با Reversal + Repost
- موتور میانگین موزون تاریخی و سپس گزینه FIFO
- واحدهای چندگانه و تبدیل کارتن/بسته/عدد
- اسکن بارکد با دوربین
- چند انبار و انتقال بین انبارها
- تخصیص دریافت/پرداخت به چند فاکتور و تسویه ترکیبی حرفه‌ای
- سال مالی واقعی، بستن دوره و سند افتتاحیه
- Backup رمزگذاری‌شده قابل انتقال بین دستگاه‌ها
- Biometric کامل
- چاپگر حرارتی و قالب‌های چاپ
- Release امضاشده با Keystore ثابت
