# حسابدار (App-Hesabdar)

«حسابدار» یک نرم‌افزار حسابداری فارسی، آفلاین و Android-first است. داده‌های اصلی مالی در Room/SQLite داخل دستگاه نگهداری می‌شوند و عملکرد پایه برنامه به سرور نیاز ندارد.

## نسخه پایدار

- Version Name: `1.0.0`
- Version Code: `7`
- Application ID: `com.waxew.hesabdar`
- Room Schema: `6`
- Kotlin + Jetpack Compose + Material 3
- minSdk: 24
- targetSdk / compileSdk: 35
- Java/Kotlin target: 17
- رابط فارسی و RTL

## امکانات نسخه 1.0.0

### داشبورد و رابط
- داشبورد فروش، خرید، مطالبات، بدهی‌ها، درآمد، هزینه، چک‌های باز و هشدار موجودی.
- Drawer راست‌به‌چپ با پروفایل و تصویر محلی.
- Bottom Navigation، صفحه تماس و درباره نرم‌افزار.
- نمایش نسخه واقعی Build از `BuildConfig.VERSION_NAME`.
- پشتیبانی System / Light / Dark.
- کلید Back ابتدا Drawer یا صفحه داخلی را می‌بندد/برمی‌گرداند و از صفحات فرعی مستقیماً برنامه را نمی‌بندد.

### اشخاص
- ثبت طرف‌حساب.
- پروفایل مالی و صورت‌حساب زمانی.
- محاسبه مانده از گردش واقعی فاکتور و دریافت/پرداخت، نه از یک فیلد مانده قابل ویرایش.

### کالا، خدمت و انبار
- کالا و خدمت، SKU، بارکد متنی، دسته‌بندی، واحد، قیمت خرید و فروش.
- موجودی و حداقل موجودی.
- کارتکس کالا و اصلاح دستی با Audit Trail.
- موجودی افتتاحیه هنگام ساخت کالا در کارتکس با نوع `OPENING` ثبت می‌شود.
- خدمت روی موجودی انبار اثر نمی‌گذارد.

### فاکتور و معاملات
- فروش، خرید، برگشت از فروش و برگشت از خرید.
- فاکتور چندردیفی.
- تخفیف مبلغی، مالیات درصدی و هزینه حمل/ارسال.
- شماره سند یکتا و پایدار.
- وضعیت‌های `POSTED`، `VOIDED` و `REVERSAL`.
- ابطال فروش/خرید با سند معکوس؛ سند اصلی حذف یا بازنویسی نمی‌شود.
- Snapshot بهای واحد ردیف برای حفظ تاریخچه گزارش سود.
- PDF فاکتور و CSV فاکتورها.

### خزانه و حسابداری دوبل
- صندوق و حساب بانکی.
- دریافت، پرداخت، درآمد و هزینه.
- هر عملیات پولی باید به صندوق یا بانک فعال متصل باشد.
- تسویه فاکتور همزمان در `payments` و `cash_entries` ثبت می‌شود و مانده خزانه را تغییر می‌دهد.
- `cash_entries` دارای `sourceType/sourceId` است تا حرکت خزانه به منبع اصلی خود قابل ردیابی و در ابطال قابل برگشت باشد.
- حساب‌های سیستمی صندوق، بانک، دریافتنی، پرداختنی، موجودی، مالیات، فروش، بهای تمام‌شده، هزینه و درآمد.
- سند دوبل خودکار برای فاکتور و گردش نقدی.
- سند دستی با کنترل برابری بدهکار/بستانکار.
- تراز آزمایشی و گزارش‌های حرفه‌ای پایه.

### چک، اقساط و یادآوری
- چک دریافتی و پرداختی با وضعیت‌های عملیاتی.
- اقساط و ثبت پرداخت کامل/ناقص.
- جلوگیری از ایجاد قسط صفر و جلوگیری از پرداخت بیش از مانده قسط.
- اعلان آفلاین سررسید چک و قسط.

### امنیت، Backup و خروجی
- PIN محلی با مشتق‌سازی امن رمز.
- Backup محلی SQLite با WAL checkpoint.
- Backup قابل‌انتقال `HDBX` با کلید مشتق‌شده از رمز کاربر و `AES-GCM`.
- فرمت HDBX به Android Keystore وابسته نیست و با همان رمز روی دستگاه دیگر قابل بازیابی است.
- قبل از Restore رمزگذاری‌شده، Backup اضطراری از وضعیت فعلی ایجاد می‌شود.
- کنترل Header دیتابیس و صحت AES-GCM هنگام Restore.
- PDF و CSV بدون وابستگی به سرویس آنلاین.

## یکپارچگی داده و سیاست Update

- مبلغ مالی با `Long` ذخیره می‌شود؛ از Float/Double برای پول استفاده نمی‌شود.
- تمام تغییرات چندجدولی حساس داخل Room Transaction انجام می‌شوند.
- `fallbackToDestructiveMigration` در Production استفاده نمی‌شود.
- Migrationهای صریح از Schema 1 تا Schema 6 وجود دارند.
- Application ID ثابت می‌ماند.
- Version Code در هر انتشار افزایش می‌یابد.
- سند نهایی مالی Hard Delete نمی‌شود؛ اصلاح جدی با Void/Reversal انجام می‌شود.
- اطلاعات نسخه‌های قبلی در Upgrade حفظ می‌شوند.

## Build و CI

GitHub Actions روی `main`، `develop-v1` و `release-v1` اجرا می‌شود:

```bash
gradle :app:testDebugUnitTest --stacktrace
gradle :app:assembleDebug --stacktrace
```

Artifact نصب‌شونده تستی:

`App-Hesabdar-v1.0.0-debug`

### Release Signing

Keystore خصوصی و رمزهای آن در Repository ذخیره نمی‌شوند. Workflow فقط وقتی چهار Secret زیر تنظیم باشند APK Release امضاشده می‌سازد:

- `HESABDAR_RELEASE_KEYSTORE_BASE64`
- `HESABDAR_RELEASE_KEYSTORE_PASSWORD`
- `HESABDAR_RELEASE_KEY_ALIAS`
- `HESABDAR_RELEASE_KEY_PASSWORD`

در صورت وجود آن‌ها Artifact زیر ساخته می‌شود:

`App-Hesabdar-v1.0.0-release`

## تست‌ها

Unit Testها شامل محاسبات فاکتور، شماره سند، تاریخ شمسی، تقسیم امن اقساط و بردار استاندارد PBKDF2-HMAC-SHA256 هستند. Build فقط پس از موفقیت تست‌ها APK تولید می‌کند.

## بعد از 1.0

قابلیت‌هایی مثل تخصیص پرداخت به چند فاکتور، چندانبار، چندواحدی پیشرفته، بارکد دوربین، بهای تمام‌شده Weighted Average/FIFO کامل، سال مالی و بستن دوره پیشرفته، چاپ حرارتی، Import گسترده Excel و Sync اختیاری ابری برای نسخه‌های بعدی نگهداری می‌شوند؛ این موارد نباید هسته پایدار آفلاین 1.0 را بی‌ثبات کنند.
